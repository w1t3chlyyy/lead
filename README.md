# Hustlify Leads Bot — Vercel + Supabase + Qwen + cron-job.org

Ищет **свежие (≤ 3 дней)** сообщения клиентов по **всем публичным чатам Telegram**, а не только по тем, куда вступил аккаунт.
Всё управление — в чате с ботом, на инлайн-кнопках. Мини-апп один и только для статистики.

```
cron-job.org (каждые 2 мин) ─▶ Vercel /api/scan ─▶ Telethon SearchGlobal (≤3 дня)
                                   │                 └▶ regex-префильтр ─▶ Qwen (+каталог из Supabase)
                                   ▼                                         │
                         Supabase (лиды, фразы, настройки, дедуп, статистика) ◀┘
Telegram ◀─▶ Vercel /api/bot (вебхук, кнопки)        Mini App /  ◀─ /api/stats (только владелец)
Vercel Cron: /api/digest раз в сутки (сводка + чистка)
```

## Что умеет бот (всё кнопками)
- 📥 Новые / 🔧 В работе / 🗂 Все лиды со страницами; карточка: текст, чат, автор, возраст, оценка, причина, черновик
- ✅ В работу → 💰 Сделка / 🚫 Не сложилось / ❌ Не лид (пометки «Не лид» учатся: Qwen видит последние 5 как антипримеры)
- 🔁 Другой черновик ответа, кнопки «Открыть сообщение» и «Написать автору»
- 🔎 Искать сейчас (ручной скан), ⏸ пауза, возраст 1–3 дня, порог 50–80%, число фраз за запуск
- 🔑 Фразы поиска: вкл/выкл, удалить, добавить своей фразой, вернуть стартовые
- 📦 Каталог, который видит Qwen (обновление из Supabase кнопкой)
- 📊 Статистика — мини-апп: лиды по дням, воронка, статусы, топ запросов/чатов/фраз, конверсия

## Установка (≈15 минут)
1. **Supabase**: SQL Editor → вставь `supabase/schema.sql` → Run. Возьми `Project URL` и `service_role` ключ.
2. **Бот**: @BotFather → `/newbot` → токен. Свой ID узнай у @userinfobot.
3. **Юзербот**: https://my.telegram.org → API development tools → `api_id`/`api_hash`.
   Локально: `pip install telethon && python tools/gen_session.py` → строка `TG_SESSION_STRING`.
   **Используй отдельный аккаунт**, не основной.
4. **Деплой на Vercel** (любой из способов):
   - через CLI из папки проекта: `npm i -g vercel && vercel --prod`, затем добавь переменные
     (`vercel env add ИМЯ production` или в Dashboard → Settings → Environment Variables) и повтори `vercel --prod`;
   - или залей папку в GitHub-репозиторий и сделай Import в Vercel.
   Точка входа — `app.py` (FastAPI), Vercel подхватывает её сам, Framework Preset оставь «Other»/автоопределение.
   Переменные берёшь из `.env.example` (`APP_URL` можно не задавать, Vercel подставит домен сам).
   `CRON_SECRET` придумай сам: только `A-Z a-z 0-9 _ -`, длинный и случайный.
5. **Вебхук**: открой в браузере `https://<твой-домен>/api/setup?key=<CRON_SECRET>`.
   Ставит вебхук, команду `/start` и кнопку «Статистика».
6. **cron-job.org** → Create cronjob:
   - **URL**: `https://<твой-домен>/api/scan?budget=18`
   - **Schedule**: every 2 minutes (можно каждую минуту: параллельные запуски отсекаются замком)
   - вкладка **Advanced** → Request method: `POST`; Headers: `Authorization` = `Bearer <CRON_SECRET>`
   - Request timeout оставь 30 с (максимум у сервиса), включи уведомление о сбоях.
   Ответ запуска — JSON со статистикой (фраз, найдено, свежих, лидов), его видно в истории задания.
7. Напиши боту `/start`.

Сводка раз в сутки идёт через Vercel Cron из `vercel.json` (на Hobby это разрешено). Если не нужна, удали блок `crons`.

## Как обеспечена свежесть
- `SearchGlobalRequest(min_date = сейчас − N дней)` + повторная проверка `message.date >= cutoff` в коде. N = 1–3 из настроек, выше 3 не поднимается.
- Дедуп в Supabase по сообщению и по хэшу текста (кросс-посты); ключи старше 5 суток чистятся.

## Важно знать
- **Квота Qwen.** К модели доходят только сообщения, прошедшие regex-префильтр и дедуп; плюс дневной потолок `LLM_DAILY_CAP` (по умолчанию 300 вызовов). Исчерпан — сканы пропускаются до полуночи UTC.
- **Vercel не держит постоянное соединение**, поэтому «живого потока» по твоим группам нет: вместо него глобальный поиск
  каждые ~5 минут. Он покрывает все публичные группы, но выдача Telegram ограничена (50 на страницу, 2 страницы на фразу),
  поэтому важны хорошие фразы: добавляй свои в боте.
- За запуск обрабатывается до `queries_per_run` фраз (самые давно не проверявшиеся), но не дольше бюджета времени; сколько успело, столько и обработано.
- Telegram не любит одну сессию из двух мест одновременно: в `lb_lock` стоит замок, параллельные запуски пропускаются.
  Если сессию всё же сбросит (бот пришлёт ⚠️) — сгенерируй `TG_SESSION_STRING` заново и обнови переменную в Vercel.
- cron-job.org обрывает ожидание ответа через 30 с, поэтому скан по умолчанию укладывается в ~18 с (`?budget=`). Больше фраз за запуск = ставь чаще, а не дольше.
- Бот ничего не пишет людям сам: отвечай вручную по кнопке, иначе спам и бан аккаунта.
- `SUPABASE_SERVICE_KEY` и `TG_SESSION_STRING` держи только в переменных Vercel.
- Если магазин в другом проекте Supabase — укажи `SHOP_SUPABASE_URL`/`SHOP_SUPABASE_KEY`.
